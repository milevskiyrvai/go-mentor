# Чеклист проверки дизайна на соответствие ТЗ

> По этому чеклисту проверяется КАЖДЫЙ макет, который выдаёт нейронка-дизайнер (claude.ai/design). Цель — поймать пропущенные экраны, потерянные элементы и сломанные взаимосвязи **до** переноса в код. Источник истины — `TZ/ТЗ к Хакатону (itrostik).pdf` (раздел 25 «Acceptance Criteria») и `DESIGN_BRIEF.md`.
>
> Легенда: `[ ]` не проверено · `[x]` есть и корректно · `[~]` есть, но с замечанием · `[!]` ОТСУТСТВУЕТ / нарушает ТЗ.

---

## 0. Полнота карты экранов (ничего не пропущено)

**Общие**
- [ ] Login (логин+пароль, состояние ошибки)
- [ ] Выбор роли (мультироль)
- [ ] Публичный профиль — состояние «открыт»
- [ ] Публичный профиль — состояние «закрыт» (только имя/аватар/telegram)

**Student** — [ ] Дашборд · [ ] Roadmap · [ ] Достижения · [ ] Бонусы · [ ] Собеседования · [ ] Календарь · [ ] Профиль

**Buddy** — [ ] Мои ученики · [ ] Карточка ученика · [ ] Собеседования · [ ] Календарь · [ ] Профиль

**Admin** — [ ] Дашборд · [ ] Пользователи · [ ] Roadmap · [ ] Достижения · [ ] Заявки 1×1 · [ ] Аналитика

## 1. Авторизация (ТЗ §25.1)
- [ ] Вход по логину и паролю
- [ ] Пользователь с несколькими ролями может выбрать роль
- [ ] Выбранная роль влияет на интерфейс (разные сайдбары student/buddy)
- [ ] Есть кнопка выхода
- [ ] (нет email/восстановления пароля — лишнего быть не должно)

## 2. Student Roadmap (ТЗ §25.2)
- [ ] Список блоков
- [ ] Материалы внутри блоков
- [ ] Материалы разделены на **Теория / Вопросы / Практика / Домашка**
- [ ] Материалы — **карточки-эмбеды**, не список ссылок
- [ ] Видно обязательность материала (обязательный / опциональный)
- [ ] Можно отметить материал просмотренным (контрол отметки)
- [ ] Прогресс блока (%) отображается
- [ ] Статус «Ожидает подтверждения от Buddy» виден
- [ ] 4 статуса блока визуально различимы: не начат / в процессе / ожидает / подтверждён
- [ ] НЕТ кнопки «отправить блок на проверку» (переход автоматический — §7.3)

## 3. Buddy progress (ТЗ §25.3)
- [ ] Список своих учеников
- [ ] Можно открыть карточку ученика
- [ ] Виден прогресс по блокам
- [ ] Кнопка «Подтвердить блок»
- [ ] В карточке: профиль, текущий блок, %, статусы блоков, просмотренные материалы, собеседования, финалки, история активности
- [ ] Buddy НЕ видит бонусы/историю бонусов ученика (на макете карточки их быть не должно)
- [ ] Индикатор «N дней без активности»
- [ ] Кто ожидает подтверждения — акцентирован

## 4. Admin roadmap (ТЗ §25.4)
- [ ] Создание/редактирование блоков
- [ ] Удаление/деактивация блоков
- [ ] Изменение порядка блоков (drag-and-drop, видна обратная связь)
- [ ] Создание/редактирование материалов
- [ ] Удаление/деактивация материалов
- [ ] Изменение порядка материалов (drag-and-drop)
- [ ] Пометка обязательности материала
- [ ] Поля материала в форме: заголовок, описание, тип (теория/вопросы/практика/домашка), тип контента, url/текст, превью, источник

## 5. Достижения (ТЗ §25.5)
- [ ] Каталог достижений
- [ ] Достижения в профиле/на дашборде
- [ ] У достижений есть картинки/бейджи
- [ ] Видны условия («что сделать»)
- [ ] Видна награда в бонусах
- [ ] Состояния: получено / не получено (locked)
- [ ] Прогресс до достижения (напр. `7 / 10`)
- [ ] Визуальное уведомление о получении (toast/modal/баннер) — есть макет
- [ ] Ровно **14** достижений из §14, без выдуманных «rare/секретных»
- [ ] Награды соответствуют §14 (10/25/50/40/50/60/70/90/30/50/120/20/300/0), а не преувеличенные

## 6. Бонусы (ТЗ §25.6)
- [ ] Баланс бонусов
- [ ] История операций (дата, тип, количество, причина)
- [ ] Конвертация бонусов в скидку
- [ ] Правило **100 бонусов = 1% скидки** (не другое)
- [ ] Бонусы списываются при конвертации
- [ ] Потолок скидки **15%**
- [ ] Кнопка конвертации блокируется при 15% (есть disabled-состояние)
- [ ] 5 типов операций: начисление за достижение / конвертация / трата 1×1 / ручная корректировка / возврат

## 7. Заявки 1×1 (ТЗ §25.7)
- [ ] Student может создать заявку (1000 бонусов = 1 заявка)
- [ ] При создании бонусы НЕ списываются
- [ ] Список «Мои заявки» со статусами (pending/approved/rejected/completed/cancelled)
- [ ] Admin: список заявок (ученик, дата, статус)
- [ ] Admin: approve / reject / complete / cancel
- [ ] approve визуально показывает списание 1000 бонусов; при нехватке — недоступно

## 8. Собеседования (ТЗ §25.8)
- [ ] Student добавляет real ссылкой (форма: компания, позиция, грейд, стек, дата, url, результат)
- [ ] Результаты real: offer / reject / pending / no_result
- [ ] Buddy создаёт mock
- [ ] Buddy завершает mock (статус completed)
- [ ] Buddy пишет фидбэк
- [ ] Student видит свои mock и real
- [ ] Real видны в общем каталоге
- [ ] Mock НЕ в общем каталоге
- [ ] В общем каталоге имена видны и кликабельны → публичный профиль

## 9. Профиль и приватность (ТЗ §25.9)
- [ ] Редактирование: аватар, имя, «о себе»
- [ ] Telegram username отображается, НЕ редактируется пользователем, кликабельная ссылка
- [ ] Публичный профиль открывается у другого пользователя
- [ ] Переключатель «скрыть расширенную информацию» (одна настройка)
- [ ] Закрытый профиль: только имя/аватар/telegram
- [ ] Buddy всё равно видит прогресс своего ученика (исключение по видимости)

## 10. Календарь (ТЗ §25.10)
- [ ] Buddy создаёт события
- [ ] Buddy видит события по своим ученикам
- [ ] Student видит свои события (только просмотр)
- [ ] Представление «календарь» (сетка)
- [ ] Представление «ближайшие 7 дней»
- [ ] Фильтры (для buddy): по ученику, по типу, по дате
- [ ] 6 типов событий различимы: mock / real / ревью блока / техничка / прожарка / custom

## 11. Финальные проверки (ТЗ §9)
- [ ] Техничка и прожарка как отдельные этапы (не обычные материалы)
- [ ] Доступны только после закрытия всех основных блоков (состояние not_available до этого)
- [ ] Buddy назначает и подтверждает (статусы: not_available/available/scheduled/completed/failed)
- [ ] Видны на дашборде студента и в карточке ученика у buddy

## 12. Admin users (ТЗ §25.11)
- [ ] Создание пользователя
- [ ] Поля: логин, пароль, роли, telegram, дата начала обучения
- [ ] Назначение buddy ученику
- [ ] Смена пароля
- [ ] Редактирование данных
- [ ] Удаление (soft delete — помечен, не исчез); возможность видеть удалённых
- [ ] Роли визуально различимы

## 13. Admin аналитика (ТЗ §22)
- [ ] Количество пользователей / студентов / buddy
- [ ] Активные заявки 1×1
- [ ] Выданные достижения
- [ ] Общая активность

---

## 14. Взаимосвязи и флоу (то, что не видно на одном скрине)

- [ ] Имя пользователя кликабельно в списках/собеседованиях/достижениях → ведёт в публичный профиль
- [ ] Login → (мультироль) Выбор роли → нужный интерфейс; одна роль → сразу интерфейс
- [ ] Student-флоу проходим целиком: дашборд → roadmap → отметка материалов → авто-переход блока в «ожидает» → подтверждение → уведомление о достижении → бонусы
- [ ] Buddy-флоу: список учеников → ждёт подтверждения → карточка → подтвердить блок
- [ ] Сайдбары для разных ролей различаются и соответствуют разрешённым действиям роли
- [ ] Admin — визуально отдельная панель (другой контекст, чем student/buddy)
- [ ] Навигация между экранами одной роли консистентна (общий layout/сайдбар)

---

## 15. Состояния (часто забывают — снижает оценку)

- [ ] Пустые состояния (нет достижений/операций/событий/собеседований/учеников) — осмысленные, не «пусто»
- [ ] Загрузка (скелетоны)
- [ ] Ошибка (загрузка/логин)
- [ ] Hover/active для кликабельного
- [ ] Заблокированные действия: конвертация при 15%, approve при нехватке бонусов, финалки до закрытия блоков
- [ ] Адаптив: десктоп + планшет + мобильный (сайдбар→drawer, панели стекаются, модалки по ширине)

---

## 16. Антипаттерны (нарушение = `[!]`)

- [ ] НЕТ инструкций-подзаголовков под заголовками экранов («Перетаскивай…», «Управляйте…», «Конвертируйте…»)
- [ ] Материалы — карточки, НЕ голый список ссылок
- [ ] Достижения — коллекционные бейджи, НЕ плоский декор
- [ ] Нет сиротливых «—» / «не указано» как основного контента
- [ ] Нет придуманного функционала, которого нет в ТЗ (если только не из §27 «плюсы»)
